# G-1: аудит прогресса, 25.10.2026

## Найденные причины

- `xp.ts/lessonOpen` проверял предыдущий урок только внутри главы и `profile.level`. Поэтому первый урок каждой главы мог стать текущим одновременно с другими.
- `diagnostic.ts` повышал `profile.level` по входному тесту; `awardLesson` смешивал номер главы с уровнем XP. На экране добавлялась ещё единица. Пороги XP были 0/150/400/800/1400.
- Путь и список читали сохранённый `status`, карта дополнительно проверяла `profile.level`; рекомендации выбирали первый сохранённый `current`.
- `migrateLessonFlow` считал видео и тест пройденными по более поздним флагам старого черновика. Подтверждение просмотра не сохранялось, результат теста при миграции не проверялся.
- Вход в урок и индикатор этапов доверяли таким флагам. Облачная загрузка и объединение могли вернуть старые состояния.

## Решение

`computeCourseState` определяет один первый незавершённый урок во всём упорядоченном курсе. Завершение требует сохранённого статуса и подтверждений всех этапов. `computeStageState` проверяет явное подтверждение видео либо долю просмотра >=80%, ответы теста >=70% и три подзадачи практики. Последующие этапы зависят от предыдущих.

Загрузка, объединение и обновление прогресса нормализуют статусы и уровень. Старые неподтверждённые этапы сбрасываются; код, схемы, баланс и заработанные XP сохраняются. Награды повторно не начисляются по уже сохранённой отметке выдачи. Уровень ученика и глава курса — разные понятия; глава открывается по последовательности уроков, уровень — только по XP.

## Исполнение файла G1

- Работа ведётся в текущей папке, ветка `codex/g1-core-fixes`; контрольная точка `snapshot-2026-10-24` сохранена. Существующая непроиндексированная папка `outputs/` не изменяется.
- Присланный файл содержит G-1–G-4; выполняем все в этой сессии по прямому запросу пользователя. Разделение на прежние сессии не применяется.
- G-2 выполняется отдельным агентом; G-3 — агентом компилятора; интерпретатор G-4 — отдельным агентом. Интеграция прогресса и запуска остаётся у основного агента.
- Внешний Docker-хостинг не разворачивается: это отдельно обозначенный в плане шаг владельца. Недоступность Docker на машине будет отражена как ограничение проверки, а не как успешный Docker smoke.

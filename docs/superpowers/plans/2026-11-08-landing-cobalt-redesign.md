# ArduHub Cobalt Mono Landing Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [x]`) syntax for tracking. Работа выполняется последовательно; этот документ сам по себе не запускает разработку.

**Goal:** Пересобрать лендинг ArduHub в светлой теме Cobalt Mono, с парящими электронными компонентами на первом экране и наглядным показом процесса обучения при прокрутке.

**Architecture:** Сохранить Next.js App Router и существующие рабочие взаимодействия. Ограничить новую тему контейнером публичной главной, включая её шапку и подвал. Фон собрать из отдельных растровых рендеров с прозрачностью и CSS-анимации; сценарии продукта показать существующими компонентами схем и специально подготовленными примерами интерфейса.

**Tech Stack:** Next.js 16.4.1, React 19.3.1, TypeScript, Tailwind CSS 4, motion 12, pnpm. Новые библиотеки и WebGL для первого этапа не нужны.

**Spec:** `docs/ArduHub_landing_spec.md`, `AGENTS.md` и требования пользователя в этой беседе. Этот план описывает изменения старой спецификации; визуальные решения ниже ещё предстоит проверить на макете. Тексты и функции проверять по текущему коду, поскольку старый content deck содержит устаревшие допущения.

## Зафиксированные требования пользователя

Палитра и поверхности основаны на присланном изображении Cobalt Mono: почти белый фон, кобальтовые основные кнопки, бледные лавандовые вторичные поверхности, тонкие границы и округлые элементы. Пользователю нравятся типографика Neuralese, движение страницы и показ продукта. Не копировать сайт целиком.

Первый экран должен содержать объёмные компоненты Arduino. Пользователь отказался от следования за курсором. Платная видеогенерация не требуется: используем согласованное направление анимации кодом. Это растровые изображения с 3D-видом, а не интерактивные CAD-модели.

Референс сцены уже создан: `outputs/landing-cobalt/arduhub-hero-cobalt-v1.png`. Изображение показывает общий стиль и расположение компонентов. У него единый фон; для независимого движения деталей нужны отдельные материалы. Файл `outputs/landing-cobalt/video-prompt.md` сохраняется как необязательный вариант для будущего видео.

### Первый экран

В центре: небольшой вводный текст, крупный заголовок, короткое объяснение и основная кнопка «Начать бесплатно». Вторичный переход ведёт к показу продукта. Текст первоначально брать из `ru.hero`, редактуру проводить без новых продуктовых обещаний. Текущие большую цифру «0» и сегментную полосу предлагается убрать из первого экрана; это изменение прежней спецификации.

По краям: Arduino Uno как самый крупный объект, белая макетка, HC-SR04, синий SG90, красный светодиод и резистор. Провода использовать только там, где они не пересекают текст. Для десктопа оставить центральную область шириной примерно 50% свободной. На телефоне распределить 2–3 объекта над и под текстом вместо уменьшения всей настольной сцены.

Предлагаемые параметры парения: цикл 12–20 секунд, смещение до 8 px на десктопе и до 4 px на телефоне, поворот до 3 градусов, разные фазы. Анимировать только `transform` и `opacity`; тени статичны. Контейнеры позиционирования и анимации разделить, чтобы transforms не перезаписывали друг друга. При уходе сцены за экран или скрытии вкладки ставить движение на паузу. При reduced motion показывать статичную композицию.

### Показ продукта и структура страницы

Сохранить темы, доступ, FAQ и существующие рабочие переходы. Предлагается добавить крупную демонстрацию сразу после hero, затем вести посетителя от выбора урока к сборке и проверке схемы. Вместо череды одинаковых карточек использовать чередование текста и больших интерфейсных сцен. Существующий пятишаговый блок сохраняет управление прокруткой, кликом и клавиатурой.

Предлагаемый порядок: шапка → hero → крупная демонстрация → фактические сведения о продукте → возможности → пять шагов → банк схем → режимы практики → темы → доступ → FAQ → форма новостей → подвал. Ряд цифр оставить только с проверенными значениями и явным контекстом. Банк схем продолжает фильтровать примеры; он не должен выглядеть работающим полноценным редактором.

Сцена сборки показывает подключение LED и проверку соединения средствами существующего `CircuitScene`. Интерфейс наставника показывает только подтверждённый сценарий; пример ответа должен быть обозначен как пример. Запись действующего интерфейса допустима позже, но она не является зависимостью этого плана.

## Review Focus

1. Телефон 360 px и длинный русский текст: детали не перекрывают заголовок, обе кнопки доступны без горизонтальной прокрутки. Проверка в задаче 3.
2. Reduced motion, фоновые вкладки и уход за экран: парение выключается или приостанавливается без исчезновения контента. Проверка в задаче 3.
3. Ошибка загрузки картинок и отключённый JavaScript: текст, ссылки и статичный первый экран остаются доступны. Проверка в задачах 3 и 6.
4. Общие кнопки и CSS: `/app` и `/sign-in` сохраняют прежнюю тему и рабочие переходы. Проверка в задачах 1 и 6.
5. Быстрая прокрутка и задержка motion-чанка: шаги и фильтры продолжают работать, активный шаг не застревает. Проверка в задачах 4 и 6.

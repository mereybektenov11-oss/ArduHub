# Подключение и публикация ArduHub

По ответу пользователя проектов Supabase и Vercel пока нет. Репозиторий подготовлен; фактическое развёртывание и запись заявки не выполнены.

## Supabase

Создайте отдельный проект ArduHub. Примените `supabase/migrations/20261015190609_waitlist_signups.sql` через SQL Editor своего проекта или после привязки проекта CLI. Миграция создана командой `supabase migration new waitlist_signups`. Публичное чтение и запись закрыты, включён RLS. Сервер использует новый `sb_secret_…` ключ через заголовок `apikey`.

В `.env.local` для локальной работы или в закрытых переменных Vercel задайте `SUPABASE_URL` и `SUPABASE_SECRET_KEY`. Не добавляйте секрет в `NEXT_PUBLIC_*`, Git или сообщения. Никаких ключей в репозитории нет.

Нормализация email и уникальное ограничение таблицы защищают от повторных записей, включая одновременную отправку. Ловушка `website` отвечает успехом без записи. Лимитер допускает пять запросов за минуту; в версии v1 он хранится в памяти одного процесса, поэтому не является глобальным лимитом между экземплярами serverless. Для большого трафика его нужно заменить общим хранилищем. На Vercel используется доверенный заголовок `x-vercel-forwarded-for`; вне Vercel запросы имеют общий локальный bucket.

После подключения отправьте тестовый адрес, проверьте одну запись в таблице, повторите адрес в другом регистре и убедитесь, что запись остаётся одна. Запросы с ловушкой не должны создавать строк. Удалите тестовую строку через свой SQL Editor. Это внешняя проверка, она ещё не выполнялась.

Документация реализации: [API keys](https://supabase.com/docs/guides/getting-started/api-keys), [Grants and RLS](https://supabase.com/docs/guides/api/securing-your-api). Изменения API сверены с changelog и актуальной документацией; новые secret keys не передаются как Bearer JWT.

## Vercel

Импортируйте исходники как проект Next.js. В `vercel.json` заданы `pnpm install --frozen-lockfile` и `pnpm build`; Node.js 24. На сервере используются обычные каталоги, локальные связи на D: переносить не нужно.

Настройте окружения Preview и Production отдельно. Секреты базы задаются в каждом окружении; для Preview желательно использовать отдельный тестовый проект/ветку Supabase. `SITE_URL` должен содержать реальный канонический адрес Production. Если он не задан, страница по умолчанию закрыта от индексации.

Сначала включите приём заявок и проверьте его на Preview. Затем публикуйте Production. Команда Vercel CLI для подготовленного локального проекта: `npx vercel`; для Production: `npx vercel --prod`. До создания аккаунта и проекта эти команды не выполнялись.

## Контент перед реальным запуском

- Утвердить действительные числа уроков/схем и цену Pro. Сейчас числа обозначены как план, цена — «Скоро».
- Указать реальный контакт оператора данных и способ обработки удаления в `src/content/ru.ts`, раздел `privacy`. Сейчас опубликован честный текст подготовительной версии.
- В Vercel можно включить Web Analytics и установить `NEXT_PUBLIC_ENABLE_ANALYTICS=true`. Скрипт `/_vercel/insights/script.js` подключается только при этом флаге. Сейчас аналитика не активна, cookie не используются.
- После изменения серверной конфигурации пересобрать сайт, чтобы статичная форма отразила подключение базы.

## Заголовки и SEO

В `next.config.ts` настроены CSP, X-Content-Type-Options, Referrer-Policy, X-Frame-Options и ограничения доступа к камере/микрофону. Статическая гидратация Next.js требует разрешения встроенных скриптов; `unsafe-eval` включается только в разработке. Перевод на CSP с nonce потребует динамического рендеринга и отдельного изменения.

`/privacy` имеет собственный canonical; `/dev/*` закрыт от индексации и отсутствует в sitemap. OG-превью — `public/og.png`, 1200×630. Favicon — `src/app/icon.svg`.

Проверки для локального релиза: `pnpm lint`, `pnpm format:check`, `pnpm test:coverage`, `pnpm build`, `pnpm test:e2e`, `pnpm test:lighthouse`. Для проверки SEO с разрешённой индексацией задайте корректный `SITE_URL` перед сборкой; локальные измерения использовали `http://127.0.0.1:3000`. Эти результаты не заменяют проверку опубликованного домена.

# G1 core fixes: G-1–G-4, 25.10.2026

Источник задачи: [ArduHub_G1_core_fixes.md](ArduHub_G1_core_fixes.md). Работа выполнена локально в ветке `codex/g1-core-fixes`, от сохранённой версии `snapshot-2026-10-24`. Папка `outputs/`, локальные ключи и опубликованный сайт не изменялись.

## G-1 — последовательность курса

- Причины записаны в [PROGRESS_AUDIT.md](PROGRESS_AUDIT.md).
- `computeCourseState` задаёт единственный текущий урок во всём курсе. Путь, карта, список, вход в урок и рекомендации используют этот расчёт.
- `computeStageState` проверяет явное подтверждение видео либо >=80% просмотра, фактические ответы теста >=70% и все три шага практики. Пропавший тест не засчитывается автоматически.
- Неподтверждённые старые этапы сбрасываются. Код, схемы, XP и баланс сохраняются. Отдельная отметка уже выданной награды предотвращает повторную выдачу при повторном прохождении после миграции.
- Уровень только по XP: 0/100/250/450/700/1000 → уровни 1–6. Входной тест не открывает главы. Старт: 0 XP, 0 серия, 0 искры, 50 токенов.
- `/dev/progress`: сброс, отметка до урока N, вычисленные состояния. Скрыт в обычном production; изменения через эту страницу разрешены только без аккаунта.

## G-2 — тексты и знакомство

- `pnpm lint:copy` проверяет строковые значения/JSX и тексты контента. Дополнительно проверяются видимые тексты девяти страниц кабинета.
- Убраны постоянный баннер аккаунта, Pro, факт дня и превью лидеров на главной, хлебные крошки, лозунги и лишние подписи. Факты перенесены в загрузку; пустые расписание и рейтинг не выдают вымышленные записи за настоящие.
- При первом входе — ник до 20 символов и шесть аватаров. Сохранение выбора, приветствие и имя в меню проверены.
- Предложение сохранить прогресс показывается после первого завершения и ещё один раз через семь дней. Оно ждёт закрытия окна награды, закрывается крестиком и не возвращается после перезагрузки сразу. В профиле действие остаётся.
- Загрузка/скачивание проекта перенесены в «⋯». Локальное сохранение показывается коротким статусом. Шкала XP использует реальные новые пороги.

## G-3 — настоящий компилятор

- Существующие HTTP-сервис/Dockerfile, авторизация, ограничение до двух сборок, таймаут 20 секунд и SHA-256-кэш проверены по коду.
- Добавлены `pnpm compile:smoke`, настоящая кнопка Blink на `/dev/status` и [RUNBOOK](../compiler-service/RUNBOOK.md) с шагами Render, Cloud Run и Vercel. Проверка Blink на служебной странице обходит готовые прошивки приложения.
- Исправлены ошибочная классификация отсутствующего CLI как таймаута и завершение дочерних Linux-процессов при таймауте.
- Настоящий доверенный локальный Arduino CLI подтвердил Blink → HEX за 11603 мс, ошибку → HTTP 400/строка 3, неверный секрет → 401, повтор из кэша → тот же HEX за 2 мс.
- **Не подтверждено:** Docker build/run — на машине нет `docker`. Native-проверка не является проверкой изолированного контейнера. Внешний компилятор и Vercel-переменные не разворачивались; эти шаги оставлены владельцу, как в плане.

## G-4 — запуск без сервера и страховка

- Порядок: готовая прошивка → интерпретатор подходящего кода → сервис Arduino CLI.
- Интерпретатор использует ограниченный парсер/вычислитель без `eval` и `new Function`, виртуальные задержки, лимиты операций, глубины и вывода. Ошибки исполнения останавливают Worker. Неподдерживаемый код целиком отправляется настоящему компилятору, а не исполняется частично.
- Подключены входы схемы, цифровые выходы/PWM, порт, кнопка, потенциометр и зуммер. Все первые восемь эталонных программ прошли настоящие проверки поведения курса; мигание с `delay(500)` проверено в браузерном Worker с периодом около 1000 мс без запросов компиляции.
- После трёх последовательных сбоев сервера появляется сравнение с образцом. Ошибки программы и успешный запуск сбрасывают счётчик. Неверная схема/код не проходят сравнение; выдаются однократно 15 XP и 5 искр.
- Новая миграция `20261025154502_progress_evidence_fallback_rewards.sql` проверяет доказательства этапов, последовательность, источник, размер и единственность награды между обычным и аварийным завершением. Импорт прогресса переносит проверяемые наградные записи; при ошибке сохранения награда не отправляется до успешного повтора.
- **Облачная миграция не применялась.** Проверка выполнена на одноразовой PostgreSQL/PGlite. До публикации новой версии необходимо применить эту миграцию к Supabase.

## Проверка агентами и решения

Три агента независимо проверяли/реализовывали тексты и знакомство, компилятор/SQL, интерпретатор/схемы. При повторном обзоре исправлены потеря подтверждённого завершения при объединении, потеря источника награды, отсутствие наградных записей при импорте и отправка наград после неудачного сохранения.

Ограничения подмножества Arduino сохранены, остальные программы идут в сервис. Сравнение по образцу допускает эквивалентные пробелы и комментарии, но не произвольную смену задержки задания. Реальный запуск изменённой программы и правильность выполнения задания — отдельные проверки: работающий `delay(500)` не обязан удовлетворять заданию с `delay(250)`.

Новая версия на Vercel не публиковалась. Перед публикацией: применить новую миграцию, проверить вход/сохранение и награды на Preview; при необходимости полного Arduino — развернуть и проверить Docker-компилятор по RUNBOOK. Проверку контейнера и облака нельзя считать завершённой по локальным тестам.

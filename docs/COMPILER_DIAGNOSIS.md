# Диагностика компилятора — 21.10.2026

Подтверждены причины 1 и 2 из плана: в production-проекте Vercel нет COMPILER_URL/COMPILER_SECRET или их COMPILER_API_* аналогов; внешнего сервера компиляции нет. Владелец подтвердил отсутствие аккаунта Render/Railway/Fly.io. Локальный loopback gateway не доступен Vercel и не должен публиковаться через туннель.

Точные готовые решения уже исполняются из настоящего заранее скомпилированного HEX. Для изменённого кода нужен отдельный контейнерный сервис. Настройки Groq/YouTube к этой проблеме не относятся; их значения не читались и не изменялись.

API различает compiler_unconfigured, compiler_unreachable, compiler_timeout, compiler_busy, compiler_unauthorized, compile_error. В клиенте один автоматический повтор только для busy/timeout. Вызов health на закрытой локальной `/dev/status` ограничен пятью секундами. Production-страница статуса по-прежнему закрыта.

Для `/api/compile` задан maxDuration=45 секунд, запрос к сервису — до 30 секунд, клиент — до 32 секунд на попытку. Это укладывается в максимум Hobby даже без Fluid Compute (60 секунд); с Fluid — 300 секунд. Причина нынешнего отказа не в длительности функции: адрес вообще не подключён. Источники: https://vercel.com/docs/functions/limitations и установленная Next.js документация maxDuration.

Чтобы завершить F-6, нужен вход владельца в контейнерный хостинг. Развёртывание и оплата не выполнены. После развёртывания: проверить `/health`, задать адрес и отдельный случайный секрет в защищённых production variables Vercel, пересобрать приложение, проверить изменённый Blink и ошибочную программу. Локальный секрет не переносить.

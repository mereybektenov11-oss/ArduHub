# ArduHub: обучающая часть v2 (урок, Wokwi-детали, прошивка, проекты)

Продолжение `ArduHub_cabinet_spec.md`. Кабинет Codex построил (карта, наставники, главная), но обучающая часть не доведена. Здесь план исправления. Нумерация задач с префиксом `L2-`, чтобы не путать с прошлыми файлами.

## Что видно в текущей версии (по видео)

1. **Урок:** вместо видео заглушка «Видеоурок готовится». Блок «Коротко о главном» стоит под ней, и ученик не понимает, в каком порядке учиться.
2. **Схема:** детали нарисованы самодельными прямоугольниками (плата Arduino, резистор и светодиод как цветные коробки). Выглядит плохо и не похоже на настоящие детали.
3. **Код:** нет совсем. На странице написано «Симуляция и запуск кода появятся в следующей версии».
4. **Проекты:** отдельной категории, где ученик собирает свою идею, нет.

## Что должно быть

Порядок урока: **видео → краткий конспект → сборка схемы → ввод кода → запуск и проверка**. Детали выглядят как настоящие. Появляется раздел «Проекты» со свободной сборкой.

## Что такое «API Wokwi» и как мы его используем

Готового облачного API у Wokwi для вставки компонентов нет. Есть два открытых проекта с лицензией MIT, и они покрывают всё, что нужно:

- **`@wokwi/elements`**: веб-компоненты с точным видом Arduino и десятков деталей (светодиоды, резисторы, кнопки, экраны, датчики). Это только внешний вид, функционала симуляции в них нет. Каталог: elements.wokwi.com.
- **`avr8js`**: JavaScript-симулятор микроконтроллера ATmega328p (его использует Arduino Uno). Принимает уже скомпилированный код (`.hex`), всё остальное (подключение деталей) пишем сами.
- **Компиляция** кода Arduino в `.hex` делает Arduino CLI. У Wokwi в блоге описана именно такая схема: редактор кода, облачный сервис компиляции и симулятор. Публичный сервис Wokwi для нас не гарантирован, поэтому нужен свой сервис компиляции.

Цепочка: код ученика → наш сервис компиляции → `.hex` → `avr8js` в браузере → клей к деталям → внешний вид из `@wokwi/elements`.

[ASSUMPTION: «API Wokwi» понимается как использование открытых библиотек `@wokwi/elements` и `avr8js`, а не как внешний платный сервис. Исправь, если у вас есть доступ к иному сервису Wokwi]

# SECTION 1: SPEC

## One-line purpose
Ученик на каждом уроке смотрит видео, читает короткий конспект, собирает схему из настоящих на вид деталей, пишет код и запускает его в симуляции, а в разделе «Проекты» собирает собственные идеи.

## Users and use cases
- As a новичок, я хочу идти по понятным шагам (посмотрел, понял, собрал, написал, запустил), so that мне не нужно гадать, что делать дальше.
- As a ученик, я хочу видеть на схеме настоящие детали, so that я узнаю их в реальной жизни.
- As a ученик, я хочу ввести код и увидеть, как схема оживает, so that я понимаю связь кода и железа.
- As a ученик, я хочу получать понятное объяснение ошибки компиляции, so that я не застреваю на непонятных сообщениях.
- As a ученик, я хочу собрать свою идею без пошаговых ограничений, so that я проверю, чему научился.
- As a жюри, я хочу пройти один урок целиком (видео, конспект, схема, код, запуск), so that я увижу работающий продукт.

## Requirements
1. Страница урока состоит из пяти шагов с индикатором: Видео, Тема, Схема, Код, Запуск.
2. Шаг «Видео» показывает видео по ссылке урока (YouTube или файл). Следующий шаг открывается после просмотра не менее 80% видео или нажатия «Я посмотрел».
3. Шаг «Тема» показывает конспект из 3-5 коротких блоков (заголовок, 1-3 предложения, при необходимости рисунок детали из Wokwi) и кнопку «Понятно».
4. Шаг «Схема» открывает рабочую область с редактором. Следующий шаг открывается, когда проверка схемы пройдена.
5. Шаг «Код» открывает вкладку кода. Код пишется в режиме «заполни пропуски», «напиши сам» или «найди ошибку» (задаёт урок).
6. Шаг «Запуск»: код компилируется, схема запускается в симуляции, поведение сравнивается с ожидаемым. Урок считается пройденным, когда проверка поведения пройдена.
7. Детали в палитре и на полотне отображаются компонентами `@wokwi/elements`. Самодельные прямоугольники удаляются.
8. Провода присоединяются к реальным пинам деталей (по данным `pinInfo` элементов), имеют цвета и изгибы.
9. Монитор порта показывает вывод `Serial.print`.
10. Ошибки компиляции показываются в строках кода и объясняются простым русским языком.
11. Подсказки по шагам «Схема» и «Код» открываются по нарастанию: намёк, уточнение, ответ.
12. Черновик каждого урока (схема и код) сохраняется автоматически и восстанавливается при возвращении.
13. В кабинете есть раздел «Проекты» (пункт меню) с галереей «Мои проекты» и «Идеи».
14. Проект: название, описание идеи, схема, код. Сохраняется на устройстве, можно переименовать, удалить, экспортировать и импортировать файлом.
15. В проекте нет пошаговых ограничений: доступна вся палитра, схема и код, запуск и монитор порта.
16. Наставник может разобрать проект: что работает, что рискованно, какой следующий шаг.
17. Симуляция не блокирует интерфейс (выполняется в отдельном потоке).
18. Лицензии Wokwi Elements и AVR8js (MIT) указаны в файле лицензий и на странице «О проекте».

[ASSUMPTION: симулятор поддерживает только Arduino Uno (ATmega328p)]
[ASSUMPTION: в v2 симулируются: светодиод, RGB-светодиод, кнопка, потенциометр, зуммер, фоторезистор, монитор порта, PWM. Остальные детали (сервопривод, LCD1602, 7-сегментный индикатор, HC-SR04, DHT22) подключаются отдельной задачей и пока показываются как «только внешний вид»]
[ASSUMPTION: видео уроков предоставляет команда, в данных стоят заглушки `[ВСТАВИТЬ ССЫЛКУ]`]
[ASSUMPTION: макетная плата с внутренними соединениями добавляется отдельной задачей, до этого схемы собираются прямыми проводами между пинами]

## Edge cases
- **Видео недоступно или не загрузилось:** показывается сообщение и кнопка «Продолжить без видео», шаг не блокирует урок навсегда.
- **Ученик перемотал видео:** засчитывается фактическое время просмотра, а не позиция перемотки.
- **Возврат на пройденный шаг:** доступен, результаты не сбрасываются.
- **Схема сменилась после прохождения шага «Код»:** шаг «Запуск» помечается «нужно проверить заново».
- **Деталь добавлена без поддержки симуляции:** на ней метка «Только внешний вид», при запуске предупреждение, схема не ломается.
- **Провод к пину, которого нет в `pinInfo`:** соединение отклоняется.
- **Два провода на один пин, замыкание питания с землёй:** разрешено рисовать, при запуске предупреждение о коротком замыкании.
- **Код не компилируется:** запуск не стартует, ошибки подсвечены, объяснение показано.
- **Сервис компиляции недоступен:** сообщение «Не получилось проверить код, попробуй ещё раз» и кнопка «Повторить», введённый код сохраняется.
- **Слишком большой код (больше 16 КБ):** отклоняется с понятным сообщением.
- **`loop()` бесконечный:** это норма, интерфейс не зависает, остановка кнопкой «Стоп».
- **Программа ничего не выводит и не мигает:** отчёт говорит «Пин 13 не менялся, проверь `pinMode` и `digitalWrite`».
- **Перезагрузка страницы во время запуска:** симуляция останавливается, код и схема восстановлены из черновика.
- **Вкладка скрыта:** симуляция ставится на паузу.
- **Хранилище браузера недоступно:** черновики и проекты живут в памяти, показывается предупреждение «Не сохранится».
- **Лимит проектов (20) достигнут:** предложение удалить один, создание блокируется.
- **Импорт повреждённого файла проекта:** отклоняется с сообщением, существующие проекты не затронуты.
- **Сенсорный экран:** детали перетаскиваются пальцем, провод создаётся двумя касаниями, на телефоне рабочая область занимает всю ширину.
- **Уменьшить анимацию:** переходы шагов и свечение светодиода без плавных эффектов, но состояние видно.

## Design notes
- Полотно редактора: светлый кремовый фон `--cream-100` с точечной сеткой, рамка 20-24 px, детали Wokwi на нём. Боковая палитра с превью деталей (настоящие элементы, уменьшенные).
- Шаги урока: горизонтальный индикатор (пройден, текущий, закрыт) в стиле тура кабинета, переходы между шагами плавные (токены `motion.ts`).
- Левая колонка: направляющая панель текущего шага (видео, конспект, задание, подсказки). Правая: рабочая область (вкладки «Схема», «Код», «Монитор порта», кнопки «Запустить» и «Стоп»). На телефоне колонки идут друг под другом.
- Светодиод на схеме при запуске светится цветом детали, у PWM яркость меняется плавно.

## Data model

Документ сцены (общий для уроков и проектов, версионируется):

```
SceneDoc {
  version: 1,
  board: 'uno',
  components: { id, type, x, y, rotation, attrs: Record<string, string|number> }[],
  wires: { id, from: { componentId, pin }, to: { componentId, pin }, color, bends: {x,y}[] }[]
}
```

Каталог деталей (`domain/parts/catalog.ts`): для каждого типа: `type`, русское название, тег элемента Wokwi, список атрибутов по умолчанию (например, значение резистора, цвет светодиода), флаг `simulated: boolean`, группа палитры.

[ASSUMPTION: набор деталей v2: Arduino Uno, светодиод (цвета), RGB-светодиод, резистор (значение), кнопка, переключатель, потенциометр, фоторезистор, зуммер. Точные имена тегов (`wokwi-led`, `wokwi-resistor`, `wokwi-pushbutton` и т. п.) агент сверяет по каталогу установленной версии `@wokwi/elements`]

Урок (расширение существующего типа `Lesson`):

```
Lesson {
  id, unitId, title, topic, xp,
  video: { url, durationSec },
  theory: { blocks: { title, text, partType? }[] },
  circuit: { allowedParts: string[], starterScene?: SceneDoc, referenceScene: SceneDoc, hints: [string,string,string] },
  code: { mode: 'fill' | 'write' | 'fixbug', starter: string, blanks?: string[], hints: [string,string,string] },
  run: { checks: BehaviorCheck[], durationMs: number, serialExpected?: string }
}
```

Проверки поведения (описываются данными, а не сравнением текста кода):

```
BehaviorCheck =
  | { kind: 'pinBlinks', pin: number, minToggles: number, withinMs: number }
  | { kind: 'pinHighWhen', pin: number, input: { part: string, state: 'pressed' }, withinMs: number }
  | { kind: 'serialContains', text: string }
  | { kind: 'pwmLevel', pin: number, min: number, max: number }
```

Проект:

```
Project { id, title, idea, createdAt, updatedAt, scene: SceneDoc, code: string, thumbnailSvg: string }
```

Хранение: черновики уроков `arduhub.drafts.v1` (по `lessonId`: сцена и код), проекты `arduhub.projects.v1` (до 20, каждый до 200 КБ). Прогресс уроков (`Progress.lessons[id]`) расширяется полем `steps: { video, theory, circuit, code, run: boolean }`.

[ASSUMPTION: проекты и черновики хранятся только на устройстве, без аккаунтов и без публикации. Экспорт и импорт файлом JSON даёт перенос между устройствами]

## API contracts

**`POST /api/compile`** (проксирует в сервис компиляции)
- Вход: `{ code: string, board: 'uno' }`
- 200 `{ hex: string, warnings: Diagnostic[] }`
- 400 `{ error: "compile_error", diagnostics: { line, col, message }[] }`
- 413 `{ error: "code_too_large" }` (больше 16 КБ)
- 429 `{ error: "rate_limited" }` (больше 10 запросов в минуту на IP)
- 503 `{ error: "compiler_unavailable" }`

Сервис компиляции: принимает код, вызывает `arduino-cli compile` для платы Uno во временной папке, возвращает `.hex` или диагностику, кэширует результат по хешу кода (SHA-256), таймаут 20 секунд. Код только компилируется и никогда не исполняется на сервере.

**`POST /api/mentor`** (расширение): добавить режим `mode: 'explain_errors' | 'chat' | 'compile_error' | 'project_review'`. Для `project_review` вход содержит краткое описание схемы (список деталей и соединений) и код, ответ содержит три раздела: что работает, что рискованно, следующий шаг. Остальные коды ответов без изменений.

## Compile error explanations
Файл `services/compile/explain.ts`: словарь частых ошибок компилятора → понятный русский текст с примером исправления. Минимум: пропущена `;`, не объявлена переменная или функция, неверная скобка, опечатка в имени (`digitalwrite`), `void` без `()`, пропущено `}`. Для остальных ошибок показывается исходное сообщение компилятора и предложение спросить наставника (`mode: 'compile_error'`).

## Patterns to follow
- Продолжать структуру проекта: тексты из `content/*.ts`, цвета через токены, анимации через `motion.ts`.
- Логика (netlist, проверки, симулятор) чистыми функциями и классами без React.
- Веб-компоненты Wokwi создаются только на клиенте (динамический импорт, отключённый SSR), для JSX объявляются типы элементов.
- Симулятор живёт в Web Worker. Основной поток получает события (`pin`, `serial`, `adc`, `time`) и обновляет детали.
- Единая точка правды по пинам: `pinInfo` элемента Wokwi, а не координаты, прописанные вручную.

## Testing strategy
- **Unit (100% веток):** `netlist.ts` (из `SceneDoc` в связи), движок проверки схем на новых типах деталей, `checks.ts` (каждый вид проверки: проходит и не проходит), `explain.ts`, `migrate.ts` (старые сцены в новый формат).
- **Симулятор (интеграция):** загрузить заготовленный `blink.hex`, прогнать 3 секунды виртуального времени, убедиться, что пин 13 переключается; пример с кнопкой, потенциометром (`analogRead`), `Serial.print`.
- **Сервис компиляции:** корректный код даёт `.hex`, код с ошибкой даёт `diagnostics` с номером строки, превышение размера даёт 413, лимит запросов даёт 429.
- **Компонентные:** `LessonStepper` (гейтинг шагов), `Palette` (все детали отрисованы), `CodePanel` (пропуски, подсветка ошибки), проекты (создание, лимит, импорт).
- **E2E (Playwright):** полный урок (видео, конспект, схема, код, запуск, награда), проект (создать, собрать, запустить, сохранить, перезагрузить), мобильный 360 px.
- **Качество:** axe без нарушений serious и critical, Lighthouse на `/app/lesson/*` Performance не ниже 80.

## Security and performance constraints
- Код ученика компилируется в изолированном контейнере: без доступа к сети, лимит CPU и памяти, таймаут 20 с, временная папка удаляется после компиляции. Разрешены только стандартные заголовки Arduino и белый список библиотек (`Servo`, `LiquidCrystal`, `Wire`, `DHT` при наличии уроков, которым они нужны).
- Лимит `/api/compile`: 10 запросов в минуту на IP, максимальный размер кода 16 КБ.
- Ключи сервиса компиляции только в переменных окружения.
- Импорт проекта проверяется схемой данных (размер, версия, типы деталей из каталога), содержимое не выполняется.
- Бандл страницы редактора: не больше 400 КБ gzip, детали Wokwi импортируются по отдельным модулям, если пакет это позволяет, и только на страницах урока и проекта.
- Симуляция идёт в воркере и не должна опускать интерфейс ниже 55 fps при 60 деталях.

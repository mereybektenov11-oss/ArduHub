# Проверка дашборда и входа ArduHub

Обновление 17.10.2026: Supabase подключён после исходной проверки ниже. Реальная регистрация, вход и облачный перенос прогресса теперь проверены; текущие результаты и исправления редактора — [usability-fixes.md](usability-fixes.md).

17 октября 2026. План: `ArduHub_dashboard_auth_spec.md` (исходная копия совпадает с пользовательским файлом по SHA256).

## Проверено локально

- Production build, TypeScript, ESLint, lint:type и Prettier проходят.
- 174 модульных/интеграционных теста в 22 файлах проходят. Финальный полный запуск выполнен последовательно; ранний параллельный запуск прервался тайм-аутами трёх симуляций, последовательный запуск прошёл полностью.
- 18 проверок PostgreSQL проходят: чистая миграция, восемь таблиц с RLS, изоляция пользователей, запрет прямого изменения баланса, однократное начисление, миссии, дневной лимит, покупки, списание токенов, объединение завершений, расход бустов и проверка владения рамкой.
- Playwright: **89 passed, 1 skipped**. Проверены лендинг, туры, диагностика, игры, реальная AVR-симуляция, гостевой вход и выход, формы регистрации, меню и мобильный экран 360 px, поиск, магазин, миссии, профиль и фокус урока.
- Типографика проверена на восьми страницах при 1440 px: минимум 13 px, заголовки групп 12 px, максимум 40 px, не более семи размеров, h1 не больше 32 px. Увеличение обучающего текста и мобильный экран проверяются отдельно.
- Axe на `/sign-in`, `/app`, `/app/shop`, `/app/missions`, `/app/profile`: нет serious/critical. В регрессионной проверке урока исключён только DOM стороннего iframe YouTube: там обнаружен `aria-label` на `div` без роли; исправить чужой плеер средствами ArduHub нельзя. Разметка ArduHub проверяется.
- Lighthouse: доступность **100/100** на `/sign-in` и `/app`. Оба отчёта действительно открывают указанные страницы, вводный тур отключён через сохранённую пользовательскую настройку. Повторное измерение скорости с сохранённым состоянием дало 100 и 99; оно не представляется холодным пользовательским замером.
- В `.next/static` нет значений ключей и серверных имён переменных. Ключи не включались в исходники или этот отчёт.
- Официальные API Groq и YouTube отвечали HTTP 200. Для всех 12 уроков сохранены результаты YouTube и альтернативы. Последний реальный поток Groq: первый delta **1323 мс**, ответ не шаблонный, использован один токен платформы. Проверка YouTube через приложение читает уже заполненный серверный кэш; сам кэш заполнен реальным Data API.

Отчёты: `reports/dashboard/e2e-html/index.html`, `reports/dashboard/unit-final.log`, `reports/dashboard/verification.json`, `reports/dashboard/live-services.json`, `reports/lighthouse/dashboard/`.

## Что не подтверждено и что не выполнено

1. **Supabase не создан и не подключён.** Облачная регистрация, письма, вход со второго устройства и PostgREST/RLS в настоящем проекте не проверялись. Подготовленный реальный smoke-тест пропускается без выделенного тестового аккаунта. SQL проверен в PostgreSQL-движке PGlite с тестовыми auth-ролями; это не облачный Supabase и не многосессионный нагрузочный тест. Supabase advisors не запускались.
2. **JS-бюджет входа 120 КиБ не достигнут.** Холодный браузер загрузил **145882 байта / 142,46 КиБ gzip**. До отключения предзагрузки лендинга было 201,67 КиБ. Два общих runtime-чанка выбранных Next 16.4.1 / React уже занимают 128,57 КиБ. Порог в измерительном скрипте оставлен 120 КиБ: он сигнализирует превышение, а не скрывает его. Дальнейшее снижение потребует изменения архитектуры загрузки страницы входа или общего runtime.
3. Изолированный сервис произвольной компиляции и публичная публикация не настроены. Проверенные примеры Arduino продолжают работать локально. Гостевые покупки и прогресс не являются серверным аккаунтом.
4. Лимиты запросов в текущей версии хранятся в памяти одного серверного процесса; перед масштабированием на несколько экземпляров потребуется общее хранилище лимитов.

## Локальный запуск

Пользовательский сервер: `http://127.0.0.1:3000/sign-in` (далее «Продолжить как гость»). Для настоящих аккаунтов выполните шаги подключения Supabase из README, затем пересоберите приложение после изменения `NEXT_PUBLIC_*`.

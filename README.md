# ArduHub

Лендинг образовательной платформы Arduino по `docs/ArduHub_landing_spec.md`. Все секции реализованы в заданном порядке: hero со схемой, план курса, возможности, пять шагов, фильтруемый банк, три режима, темы, тарифы, FAQ, ранний доступ и подвал.

Проект включает кабинет ученика на `/app`: диагностику, карту уровней, три мини-игры, словарь, локальный и облачный прогресс, наставника с потоковыми ответами. Обучение содержит 12 практических уроков с шестью этапами, каталог деталей Wokwi, CodeMirror C++, AVR8js в Worker, Serial и свободные проекты с импортом/экспортом JSON. Текущий статус — в `docs/progress.md`.

Опубликованная версия: https://arduhub.vercel.app. Регистрация доступна на `/register`, вход — на `/sign-in`. Аккаунты и прогресс подключены к Supabase; подтверждение почты отключено для прототипа, после регистрации сразу открывается кабинет, сессия сохраняется на устройстве. Пользовательский SMTP пока не настроен.

Каждый урок включает видео, теорию, тест из шести вопросов, схему, код и запуск. В браузере исполняются реальные HEX через AVR8js, результаты проверяются по сигналам. В production доступны точные заранее собранные учебные программы; изменённый код требует отдельного изолированного сервиса из `compiler-service/README.md`. Локальный Arduino CLI gateway предназначен для доверенной разработки и не опубликован. Groq и YouTube используют серверные ключи, сохранённые в окружении хостинга. Без Groq доступны учебные шаблоны. Статус облачных проверок: `docs/vercel-deployment.md`.

## Запуск

Нужны Node.js 24 и pnpm 11.25.0.

```sh
pnpm install
cp .env.example .env.local
pnpm dev
```

Откройте http://127.0.0.1:3000. Manrope и Inter с кириллицей подключены через `next/font/local`, локальные WOFF2 оптимизированы по алфавиту и весам; оригиналы и лицензии OFL сохранены в `src/fonts`. Сборка не требует доступа к Google Fonts. Увеличение масштаба, управление клавиатурой и системное уменьшение анимации поддерживаются.

## Проверки

```sh
pnpm build
pnpm lint
pnpm typecheck
pnpm test:coverage
pnpm test:e2e
pnpm format:check
```

Браузерные проверки используют установленный Google Chrome (`channel: chrome`) и сами запускают собранную страницу на порту 3100. Перед ними выполните `pnpm build`. Если Chrome отсутствует: `pnpm exec playwright install chrome`.

Для Lighthouse запустите `pnpm start --port 3100`, затем в другом терминале `pnpm test:lighthouse`. По задаче 24 конфигурация проверяет мобильные пороги 85/95/95 и CLS ≤ 0,1; отчёты остаются локально в `reports/lighthouse`. Проверки также описаны в `.github/workflows/quality.yml`.

Для профиля движения запустите production-сервер на порту 3000 и `pnpm test:motion-profile`. Команда записывает 12-секундную прокрутку в Chrome, FPS и длинные задачи в `reports/performance`. Другой адрес можно задать через `PROFILE_URL`. Это локальная лабораторная проверка, а не гарантия одинаковой скорости на всех устройствах.

Неподвижные диаграммы используют общий `public/circuit-static.svg`, полученный из `CircuitScene` и токенов цветов. После изменения самой схемы выполните сборку и `node scripts/snapshot-circuit.mjs`, затем пересоберите сайт. Анимированные провода используют исходный SVG-компонент.

Тесты API подменяют базу: успешные тесты не означают, что настроена реальная запись в Supabase. Проверка формы в браузере использует подменённые ответы 201/429/500 и сетевую ошибку. Реальное сохранение проверяется только после подключения проекта.

## Структура

- `src/app/app`: кабинет с восемью разделами, динамическими уровнями, уроками, проектами и играми; `/api/mentor` — серверный адаптер наставника, `/api/compile` — прокси изолированной сборки.
- `src/domain`: чистая логика проверки схем, прогресса и хранилища; тексты кабинета в `src/content/cabinet.ru.ts`, доступном через `ru.ts`.
- `src/app`: главная, `/privacy`, служебные `/dev/circuits` и `/dev/motion`, SEO и `POST /api/waitlist`.
- `src/components/sections`: независимые секции; общие элементы в `ui`, схемные SVG в `circuit`.
- `src/content/ru.ts`: русский контент и типизированные данные. 12/60/20 обозначены как план, цена Pro не придумана.
- `src/lib`: фильтры, валидация, серверное сохранение, лимитер и хуки движения.
- `supabase/migrations`: созданная CLI миграция таблицы заявок, уникальность email, RLS и закрытый публичный доступ.
- `tests`: unit/API и браузерные сценарии, включая JavaScript-off и reduced motion.
- `reference`: локальные кадры для визуальной сверки, исключены из Git.
- `docs/progress.md`: выполненная задача, проверки, допущения и следующий этап.

Порядок подключения другой установки: `docs/deployment.md`. Текущая публикация и проверенные интеграции: `docs/vercel-deployment.md`. Значения ключей и пароли в репозиторий не включаются; заполните локальный `.env.local` по шаблону `.env.example`.

## Локальное хранение на этом компьютере

Из-за нехватки места на C: каталоги `node_modules`, `.next` и `reference` физически размещены в `D:/CodexWorkspaces/ArduHub_Software/` и доступны в проекте через связи каталогов. Исходники остаются в выбранной папке. Установка зависимостей для этого окружения выполняется через `pnpm --dir D:/CodexWorkspaces/ArduHub_Software install --store-dir D:/CodexWorkspaces/ArduHub_Software/store --prefer-offline`; после изменения зависимостей нужно предварительно скопировать туда `package.json`, `pnpm-workspace.yaml` и lockfile и вернуть обновлённый lockfile в проект. В обычной копии достаточно стандартного `pnpm install`.

Сборка и разработка используют Webpack, чтобы внешнее расположение зависимостей не мешало разрешению модулей.

## Обучение: новый план L2-1…L2-16

Текущий план и проверка: `docs/learning-v2-tasks-progress.md`, начальный аудит: `docs/STATUS.md`.

- 12 уроков, 50 деталей установленного Wokwi и собственная макетная плата ArduHub.
- Размер текста в уроке: обычный, крупный, очень крупный; сохраняется на устройстве.
- Проекты показывают реальные схемы в миниатюрах. Данные и беседы остаются в локальном хранилище браузера.
- Детали с отметкой «Только внешний вид» доступны для размещения; их поведение не эмулируется.

Для видео создайте ключ YouTube Data API v3, сохраните его в `.env.local` как `YOUTUBE_API_KEY`, затем выполните `pnpm videos:resolve`. Проверяйте `content/lesson-videos.json`: подбор основан на теме, длительности и метаданных, педагогическое качество нужно просмотреть. В `content/lesson-video-queries.json` можно задать `pinnedVideoId`, `pinnedTitle`, `pinnedChannel`. Без ключа и закреплённых видео урок продолжает работать с конспектом. API ограничивает живой подбор 20 уроками в сутки; результат сборочного скрипта сохраняется в JSON.

Для ИИ создайте ключ Groq, сохраните как `GROQ_API_KEY` только на сервере. Модели задаются через `MENTOR_MODEL` и `MENTOR_MODEL_FAST`. На 17.10.2026 модели Llama из исходного плана сняты с free/developer доступа: используются `openai/gpt-oss-120b` и `openai/gpt-oss-20b` ([официальное уведомление](https://console.groq.com/docs/deprecations)). Реальных запросов с ключом в этой поставке не проверяли. Без подключения и при ошибке доступны бесплатные шаблоны. Ответы идут SSE; расход: ceil(usage.total_tokens / 1000) демо-токенов. Начальный баланс 50; платежей нет. Сообщения и сокращённый контекст занятия передаются Groq — не вводите личные данные.

Никогда не присылайте ключи в чат и не добавляйте `.env.local` в репозиторий. После изменения окружения перезапустите сервер.

Каталог воспроизводится командой `pnpm parts:build`. Доверенные прошивки: `node scripts/build-learning-fixtures.mjs`; скрипт компилирует только примеры проекта, не пользовательский ввод. Полноценный компилятор запускается изолированно по `compiler-service/README.md`. Docker на этом компьютере отсутствует; проверка образа добавлена отдельной задачей CI, её результат пока не получен.

## Дашборд и аккаунты D-1–D-14

План: `docs/ArduHub_dashboard_auth_spec.md`. Состояние и проверка: `docs/dashboard-progress.md` и `docs/dashboard-verification.md`.

Страница входа — `/sign-in`. Без Supabase доступна кнопка «Продолжить как гость». Баланс гостя, миссии, покупки и проекты остаются на устройстве. Реальная регистрация, общий рейтинг и синхронизация требуют собственного проекта Supabase.

### Подключение Supabase

Локальный ArduHub подключён к отдельному проекту Supabase `wjdxephhhedxertzgjnu` (17.10.2026). Регистрация и вход проверены реальными запросами, перенос прогресса — в двух браузерах. По согласованию для прототипа отключено подтверждение почты. SMTP пока отсутствует, поэтому восстановление пароля письмом не проверено. Текущее состояние: `docs/usability-fixes.md`. Инструкция ниже относится к созданию другой установки.

Обновление локального запуска: изменённый Arduino-код теперь компилируется через loopback gateway с установленным CLI. Режим и ограничения: `compiler-service/README.md`. Кнопка «Запустить» находится над редактором, «Убрать все провода» — возле масштаба схемы; массовое удаление можно отменить.

1. Создайте проект в Supabase. В локальном `.env.local` укажите `NEXT_PUBLIC_SUPABASE_URL` и `NEXT_PUBLIC_SUPABASE_ANON_KEY` (publishable/legacy anon). Это публичные параметры, а доступ к данным ограничивается RLS. `SUPABASE_SERVICE_ROLE_KEY` предусмотрен только для серверных административных функций; текущие вход и прогресс его не требуют.
2. Примените миграции по порядку: `20261015190609_waitlist_signups.sql`, затем `20261017131620_dashboard_auth.sql` через SQL Editor своего проекта или Supabase CLI. На новой базе должны появиться восемь таблиц кабинета и таблица заявок. В базе ArduHub есть служебная схема `private`; не добавляйте её в Exposed schemas.
3. В Authentication включите Email. Добавьте `http://127.0.0.1:3000/auth/callback`, `http://127.0.0.1:3000/auth/callback?next=reset` и будущий HTTPS-домен в разрешённые Redirect URLs. Site URL — адрес сайта. Подтверждение почты и SMTP настраиваются владельцем проекта; для публичного сервиса не следует отключать подтверждение ради теста.
4. Для сборки, которая обязана иметь аккаунты, задайте `AUTH_REQUIRED=true`. По умолчанию гостевой режим продолжает собираться без внешней базы.
5. После изменения `NEXT_PUBLIC_*` выполните `pnpm build` и перезапустите production-сервер; для разработки перезапустите `pnpm dev`. Проверьте регистрацию, роль, выход/вход, сброс пароля, перенос гостевых черновиков и вход из второго браузера. Для автоматического smoke-теста выделенного подтверждённого аккаунта задайте только локально `E2E_AUTH_EMAIL` и `E2E_AUTH_PASSWORD`; без них сценарий честно пропускается.

Supabase-клиент браузера находится в `src/lib/supabase/client.ts`, серверный — в `server.ts`. Сессия проверяется через `getUser`, страницы охраняет `src/proxy.ts` (актуальное имя для Next 16). Балансы меняются через RPC, прямое изменение баланса закрыто. Завершённые уроки объединяются сервером под блокировкой строки; черновики сравниваются по времени. У аккаунтов отдельные кэши; несохранённые правки, удаления проектов и начисления сохраняются в локальной очереди и повторяются после подключения.

### Groq, YouTube и проверка

`GROQ_API_KEY` и `YOUTUBE_API_KEY` хранятся только в `.env.local` или в защищённых переменных сервера. Создание ключей: [Groq](https://console.groq.com/keys), [YouTube Data API](https://developers.google.com/youtube/v3/getting-started). Их значения не должны попадать в `NEXT_PUBLIC_*`. `pnpm videos:resolve` заполняет кэш 12 уроков; ключ не записывается в JSON. Без ключей работают бесплатные объяснения и запасной экран видео.

`GET /api/health` и `/dev/status` показывают только наличие настройки, а не значения и не гарантию доступности API. Они открыты в dev/preview; для локального production-сервера можно явно задать `LOCAL_DEV_STATUS=true`. На публичном production-сервере оставляйте этот флаг выключенным.

Проверки: `pnpm lint:type`, `pnpm test`, `pnpm test:db`, `pnpm test:secrets`, `pnpm test:e2e`. SQL-тесты запускают чистый PostgreSQL-движок PGlite с тестовыми auth-ролями: это проверяет SQL и RLS, но не заменяет проверку облачного Supabase Auth/PostgREST. `pnpm test:services` — отдельный реальный запрос Groq и проверка видео, выполняется только на запущенном локальном сервере с ключами.

# Сервис компиляции ArduHub

Next.js не запускает компилятор и не исполняет код на сервере. Gateway создаёт
отдельный контейнер на запрос; Arduino CLI компилирует Uno, результат исполняет
AVR8js в Web Worker браузера.

## Запуск с Docker

Из этой папки:

```powershell
docker build -t arduhub-compiler:1 .
$env:COMPILER_API_KEY = [guid]::NewGuid().ToString()
node server.mjs
```

Ключ хранится локально, не пересылается в браузер. В `.env.local` Next.js укажите
тот же ключ как `COMPILER_API_KEY` и `COMPILER_API_URL=http://127.0.0.1:8081/compile`.
Перезапустите Next.js. Gateway слушает только loopback; для отдельного сервера
нужны закрытая сеть и HTTPS-прокси. Не публикуйте Docker socket или gateway.

Каждая сборка: `--network none`, `--read-only`, `--cap-drop ALL`,
`no-new-privileges`, 1 CPU, 256 МБ, 64 процесса, временный tmpfs 96 МБ,
непривилегированный UID 65534. Таймаут CLI 20 с, контейнера 22 с;
gateway удаляет зависший контейнер. Временная папка удаляется в `finally`.
Один активный запрос, очередь не накапливается. Кэш SHA-256 ограничен 100 записями.
Разрешённые заголовки перечислены в `policy.mjs`; DHT и библиотеки новых устройств включены в Dockerfile;
образ фиксирует CLI 1.5.1 и AVR 1.8.8.

`/api/compile` ограничивает тело, код до 16 КБ и 10 запросов в минуту.
При публикации через прокси настройте доверенный источник IP; локально все
запросы считаются одним клиентом. Распределённый лимитер понадобится при
нескольких экземплярах сервера.

## Локальный режим без Docker

Для работы на этом компьютере включён явный режим `LOCAL_COMPILER=true`.
Gateway использует установленный `tools/arduino/arduino-cli.exe` и его локальный
конфиг. Старт из корня проекта:

```powershell
node --env-file=.env.local compiler-service/server.mjs
```

В `.env.local` заданы `COMPILER_API_URL=http://127.0.0.1:8081/compile`,
случайный `COMPILER_API_KEY` и `LOCAL_COMPILER=true`. Gateway слушает только
loopback и проверяет ключ. Next.js допускает в этом режиме только loopback Host
и запросы того же Origin. Компилятор получает только необходимые переменные ОС,
без ключей Groq, YouTube и Supabase. Процесс компилирует код для AVR; полученный
HEX исполняется в браузере, пользовательская программа не исполняется в Windows.

Разрешены заголовки из allow-list и числовые `#define`; другие директивы,
макросы с подстановкой токенов, встроенный ассемблер и альтернативные записи
директив отклоняются. На сборку выделяется один процесс компиляции, 20 секунд,
ограниченная глубина шаблонов и constexpr. Временная папка проверяется перед
удалением. При таймауте Windows завершает дерево процессов.

Это режим разработки для собственного кода на локальной машине, без контейнерной
изоляции и жёсткого лимита памяти. Не выставляйте его в интернет. Для сервиса с
недоверенными пользователями сохранён Docker-режим по умолчанию, описанный выше;
его запуск в этом Windows-окружении по-прежнему не проверен.

**Точные** примеры из `src/content/{sketches,hardware-examples,course-sketches,project-sketches}.json` были заранее собраны
официальным Arduino CLI 1.5.1 / AVR 1.8.8. Их реальные HEX находятся в
`src/services/compile/fixtures.json`. Только совпадение полного текста
(нормализация CRLF и краевых пробелов) выбирает прошивку из кэша; анализ текста не
подменяет компиляцию. Кэш проверяется до обращения к сервису, поэтому примеры
продолжают работать при его недоступности. Изменённый код идёт в компилятор.
Ответ содержит `source: precompiled` либо `source: service`. Схема не влияет
на выбор прошивки: она подключается к AVR отдельно.

Для воспроизведения генерации установите официальный CLI в `tools/arduino`,
ядро Uno и выполните `node scripts/build-learning-fixtures.mjs`. Скрипт работает
только с доверенными исходниками проекта. Не используйте хостовый CLI
как публичный API произвольного кода.

# Сервис компиляции ArduHub

Пошаговое подключение, smoke-проверка, Render, Cloud Run и Vercel: [RUNBOOK.md](./RUNBOOK.md). Кнопка на `/dev/status` отправляет Blink прямо в сервис, обходя кэш приложения. `pnpm compile:smoke <URL>` читает секрет из `COMPILER_SECRET`; аргумент `<SECRET>` также поддерживается для локальной проверки.

## Публичный HTTP-контейнер (F-6)

Добавлен `Dockerfile.http`: Node, Arduino CLI, ядро и все разрешённые библиотеки устанавливаются при сборке. HTTP-сервер запускается от UID 65534, слушает `0.0.0.0:$PORT`, требует `COMPILER_SECRET` для `POST /compile`; `GET /health` открыт и не раскрывает секреты. Два задания одновременно, лишние получают 429, компиляция ограничена 20 секундами. Исходник до 16 КБ проходит строгую проверку заголовков и препроцессора. Детали ошибок содержат строки исходника; временные папки удаляются после завершения. Память кэша ограничена 100 записями; дисковый кэш — в `/tmp/arduhub-hex-cache` (настраивается `COMPILER_CACHE_DIR`).

Контейнер не содержит ключей Groq/YouTube/Supabase. Компилятор получает только разрешённые системные переменные. Публичный контейнер не включает доверенный режим `LOCAL_COMPILER=true`. Это общий отдельный контейнер сервиса, а не Docker-контейнер на каждый запрос; для более строгой изоляции используйте исходный gateway с отдельными networkless jobs на своём сервере.

```sh
docker build -f compiler-service/Dockerfile.http -t arduhub-compiler-http compiler-service
docker run --rm --read-only --cap-drop=ALL --security-opt=no-new-privileges --pids-limit=128 --memory=1g --cpus=2 --tmpfs /tmp:rw,nosuid,nodev,size=256m -p 8081:8081 --env-file compiler.env arduhub-compiler-http
```

В `compiler.env` задайте только отдельный случайный `COMPILER_SECRET`, созданный `openssl rand -hex 32`. Не коммитьте файл. `/health` должен отвечать 200. Передайте Blink на `/compile` с `Authorization: Bearer ...`, затем программу с пропущенной `;`: ожидаются HEX/200 и диагностика строки/400; неверный секрет даёт 401.

### Render

Войдите в свой аккаунт Render и подключите закрытый репозиторий ArduHub. New → Web Service → Docker. Root Directory: `compiler-service`, Dockerfile: `Dockerfile.http`, health path: `/health`. Добавьте `COMPILER_SECRET` как секрет, не указывайте LOCAL_COMPILER. Порт определяется через PORT. `render.yaml` — заготовка Blueprint; перед применением выберите подходящий тариф в панели. Платный ресурс без согласия владельца не создавался.

### Railway / Fly.io

Railway: подключите репозиторий, root `compiler-service`, путь Dockerfile `Dockerfile.http`, задайте COMPILER_SECRET и health `/health`, создайте HTTPS-домен. Fly.io: используйте тот же Dockerfile, internal_port=8081, задайте секрет через менеджер secrets и ресурсы с памятью от 1 ГБ. Учтите, что публичные платформы могут не поддерживать все ограничения Docker из команды выше; не считайте их применёнными автоматически.

### Подключение Vercel

В Production variables ArduHub задайте `COMPILER_URL=https://ваш-домен/compile` и тот же `COMPILER_SECRET` как sensitive secret; удалите устаревшие COMPILER_API_* только после проверки, если они мешают приоритету. Выполните повторный production deploy. Секрет используется только серверным API Next.js, не добавляйте NEXT_PUBLIC_.

На этом компьютере Docker отсутствует. HTTP-образ собран и прошёл настоящий smoke в [GitHub Actions 39535828271](https://github.com/mereybektenov11-oss/ArduHub/actions/runs/39535828271), job compiler-libraries: Blink, кэш, 401 и ошибка строки. Отдельного внешнего хостинга нет, production Vercel к компилятору пока не подключён. Native smoke на Windows проверялся отдельно. Инструкции соответствуют [документации Render](https://render.com/docs/docker).

## Режим gateway с отдельным контейнером на запрос

Next.js не запускает компилятор и не исполняет код на сервере. Gateway создаёт
отдельный контейнер на запрос; Arduino CLI компилирует Uno, результат исполняет
AVR8js в Web Worker браузера.

## Запуск с Docker

Из этой папки:

```powershell
docker build -t arduhub-compiler:1 .
$env:COMPILER_API_KEY = [guid]::NewGuid().ToString()
node server.mjs
```

Ключ хранится локально, не пересылается в браузер. В `.env.local` Next.js укажите
тот же ключ как `COMPILER_API_KEY` и `COMPILER_API_URL=http://127.0.0.1:8081/compile`.
Перезапустите Next.js. Gateway слушает только loopback; для отдельного сервера
нужны закрытая сеть и HTTPS-прокси. Не публикуйте Docker socket или gateway.

Каждая сборка: `--network none`, `--read-only`, `--cap-drop ALL`,
`no-new-privileges`, 1 CPU, 256 МБ, 64 процесса, временный tmpfs 96 МБ,
непривилегированный UID 65534. Таймаут CLI 20 с, контейнера 22 с;
gateway удаляет зависший контейнер. Временная папка удаляется в `finally`.
Не более двух активных запросов, очередь не накапливается. Кэш SHA-256 ограничен 100 записями в памяти и 500 файлами на диске.
Разрешённые заголовки перечислены в `policy.mjs`; DHT и библиотеки новых устройств включены в Dockerfile;
образ фиксирует CLI 1.5.1 и AVR 1.8.8.

`/api/compile` ограничивает тело, код до 16 КБ и 10 запросов в минуту.
При публикации через прокси настройте доверенный источник IP; локально все
запросы считаются одним клиентом. Распределённый лимитер понадобится при
нескольких экземплярах сервера.

## Локальный режим без Docker

Для работы на этом компьютере включён явный режим `LOCAL_COMPILER=true`.
Gateway использует установленный `tools/arduino/arduino-cli.exe` и его локальный
конфиг. Старт из корня проекта:

```powershell
node --env-file=.env.local compiler-service/server.mjs
```

В `.env.local` заданы `COMPILER_API_URL=http://127.0.0.1:8081/compile`,
случайный `COMPILER_API_KEY` и `LOCAL_COMPILER=true`. Gateway слушает только
loopback и проверяет ключ. Next.js допускает в этом режиме только loopback Host
и запросы того же Origin. Компилятор получает только необходимые переменные ОС,
без ключей Groq, YouTube и Supabase. Процесс компилирует код для AVR; полученный
HEX исполняется в браузере, пользовательская программа не исполняется в Windows.

Разрешены заголовки из allow-list и числовые `#define`; другие директивы,
макросы с подстановкой токенов, встроенный ассемблер и альтернативные записи
директив отклоняются. На сборку выделяется один процесс компиляции, 20 секунд,
ограниченная глубина шаблонов и constexpr. Временная папка проверяется перед
удалением. При таймауте Windows завершает дерево процессов.

Это режим разработки для собственного кода на локальной машине, без контейнерной
изоляции и жёсткого лимита памяти. Не выставляйте его в интернет. Для сервиса с
недоверенными пользователями сохранён Docker-режим по умолчанию, описанный выше;
его запуск в этом Windows-окружении по-прежнему не проверен.

**Точные** примеры из `src/content/{sketches,hardware-examples,course-sketches,project-sketches}.json` были заранее собраны
официальным Arduino CLI 1.5.1 / AVR 1.8.8. Их реальные HEX находятся в
`src/services/compile/fixtures.json`. Совпадение нормализованного кода
(комментарии и форматирование игнорируются; литералы и границы операторов сохраняются) выбирает прошивку из кэша; анализ текста не
подменяет компиляцию. Кэш проверяется до обращения к сервису, поэтому примеры
продолжают работать при его недоступности. Изменённый код идёт в компилятор.
Ответ содержит `source: precompiled` либо `source: service`. Схема не влияет
на выбор прошивки: она подключается к AVR отдельно.

Для воспроизведения генерации установите официальный CLI в `tools/arduino`,
ядро Uno и выполните `node scripts/build-learning-fixtures.mjs`. Скрипт работает
только с доверенными исходниками проекта. Не используйте хостовый CLI
как публичный API произвольного кода.

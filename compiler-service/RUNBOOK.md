# Подключение компилятора ArduHub (G-3)

Сервис принимает `POST /compile` с JSON `{ "board": "uno", "code": "..." }` и заголовком `Authorization: Bearer <COMPILER_SECRET>`. Успех — HTTP 200 и настоящий Intel HEX; ошибка программы — HTTP 400 с `diagnostics[].line`; неверный секрет — HTTP 401. `GET /health` открыт. Максимум две активные компиляции на экземпляр; очереди нет, лишний запрос получает 429. Сборка ограничена 20 секундами, код — 16 КБ. Кэш SHA-256 хранится в памяти и во временной файловой системе контейнера; перезапуск может его очистить.

Публичный сервис запускайте **только через `Dockerfile.http`**. Обычный `Dockerfile` — образ для отдельного Docker-задания, у него нет HTTP-сервера. В `Dockerfile.http` уже установлены Node, Arduino CLI, `arduino:avr` и разрешённые библиотеки. Он слушает `0.0.0.0:$PORT` и работает от UID 65534. `LOCAL_COMPILER=true` не устанавливайте: это доверенная локальная разработка без контейнерной изоляции. Отдельный HTTP-контейнер обрабатывает несколько запросов; это не отдельная песочница на каждый запрос. Лимиты сервера и права не заменяют политику безопасности хостинга.

## 1. Проверка Docker на своём компьютере

Установите и запустите Docker Desktop с Linux-контейнерами. Из корня репозитория:

```sh
docker build -f compiler-service/Dockerfile.http -t arduhub-compiler-http compiler-service
docker run --rm --name arduhub-compiler --read-only --cap-drop=ALL --security-opt=no-new-privileges --pids-limit=128 --memory=1g --cpus=2 --tmpfs /tmp:rw,nosuid,nodev,size=256m -p 8081:8081 --env-file compiler.env arduhub-compiler-http
```

До запуска создайте игнорируемый Git файл `compiler.env` в корне с единственной переменной `COMPILER_SECRET=<случайное значение>`. Секрет можно получить локально через `openssl rand -hex 32`. Не отправляйте его в чат и не добавляйте в репозиторий. Используйте менеджер секретов для хранения. В другом терминале выполните:

```powershell
# Введите секрет локально через безопасный ввод — в историю команд он не попадает.
$compilerCredential = Read-Host 'COMPILER_SECRET' -AsSecureString
$env:COMPILER_SECRET = [System.Net.NetworkCredential]::new('', $compilerCredential).Password
pnpm compile:smoke http://127.0.0.1:8081
Remove-Item Env:COMPILER_SECRET
```

Скрипт проверяет `/health`, Blink, ошибку синтаксиса **на строке 3**, неверный секрет и повторный HEX из кэша. Вывод содержит только результат и время; секреты и тело ответов не выводятся. Также поддерживается `pnpm compile:smoke <URL> <SECRET>`, но так секрет может остаться в истории и списке процессов, поэтому предпочтительна переменная окружения. URL может оканчиваться на `/compile` или быть корнем сервиса. Не передавайте секрет внутри URL.

## 2. Render

1. Подготовьте репозиторий с `compiler-service/`, войдите в Render и подключите этот репозиторий.
2. Создайте **New → Web Service**. Выберите ветку с этими изменениями, язык **Docker**, Root Directory `compiler-service`, Dockerfile Path `Dockerfile.http`. Docker Command оставьте пустым, используется ENTRYPOINT образа.
3. Выберите регион и ресурсы. Для начала ориентируйтесь на 1 ГБ памяти; при двух одновременных сборках проверяйте фактическое потребление. Условия, засыпание и стоимость выбранного тарифа смотрите в панели до создания платного ресурса.
4. В Environment добавьте `COMPILER_SECRET` с отдельным случайным значением. Не добавляйте ключи Supabase/Groq/YouTube. `PORT` берётся из окружения Render, `COMPILER_CONTAINER=true` встроен в образ. `LOCAL_COMPILER` должен отсутствовать.
5. Установите Health Check Path `/health`, запустите Deploy и дождитесь успешной сборки. В логах должна появиться строка `ArduHub container compiler service ready`.
6. Откройте HTTPS-адрес сервиса с `/health`. Ожидается `{ "ok": true, "mode": "container", ... }`. Запустите `pnpm compile:smoke https://адрес-сервиса` с локальной переменной `COMPILER_SECRET` из шага 1.
7. Если сервис засыпает, учитывайте холодный старт. Внешний монитор `/health` настраивайте по правилам выбранного тарифа; он не гарантирует постоянную готовность.

Описание настроек сверено с [официальной документацией Docker на Render](https://render.com/docs/docker).

## 3. Google Cloud Run

1. В Google Cloud Console выберите свой проект, проверьте подключение биллинга и условия тарифа. Включите Cloud Run API, Artifact Registry API и Secret Manager API. Здесь сервисы автоматически не создавались.
2. В Artifact Registry создайте **Docker** repository, например `arduhub`, в выбранном регионе. Скопируйте полное имя образа вида `REGION-docker.pkg.dev/PROJECT_ID/arduhub/compiler:g3`. Замените `REGION` и `PROJECT_ID` в командах ниже своим проектом и регионом.
3. Установите Google Cloud CLI, выполните вход и настройте Docker credential helper. Сборка использует именно HTTP Dockerfile:

```sh
gcloud auth login
gcloud auth configure-docker REGION-docker.pkg.dev
docker build --platform linux/amd64 -f compiler-service/Dockerfile.http -t REGION-docker.pkg.dev/PROJECT_ID/arduhub/compiler:g3 compiler-service
docker push REGION-docker.pkg.dev/PROJECT_ID/arduhub/compiler:g3
```

4. В Secret Manager создайте секрет `arduhub-compiler-secret` со случайным значением. Не передавайте значение в командах. Создайте отдельный service account для компилятора и выдайте ему **Secret Manager Secret Accessor** только на этот секрет.
5. Cloud Run → **Deploy container**: выберите загруженный образ, тот же регион, service account из шага 4. Container port `8081`, CPU 2, memory 1 GiB как начальная конфигурация, concurrency 2, request timeout 60 секунд, minimum instances 0, maximum instances 1 на время проверки. Увеличение числа экземпляров увеличит общий лимит активных сборок и расходы. Внутренний таймаут одной сборки по-прежнему 20 секунд.
6. В Variables & Secrets добавьте **Reference a secret**: переменная `COMPILER_SECRET`, секрет из шага 4, зафиксированная версия (например `1`). Не устанавливайте `LOCAL_COMPILER`. Оставьте команду запуска из Dockerfile.
7. Разрешите публичный HTTP-вызов сервиса: Next.js использует собственный Bearer-секрет, а не Google Identity token. `/health` будет открыт, `/compile` проверяет секрет. Если политика организации запрещает публичный вызов, потребуется отдельная интеграция IAM, которой в текущем приложении нет.
8. После развёртывания проверьте HTTPS `/health`, затем `pnpm compile:smoke https://адрес.run.app` с тем же секретом в локальном окружении. При OOM увеличьте память; при ошибке доступа к секрету проверьте service account и выбранную версию.

Официальные справки: [развёртывание контейнеров](https://cloud.google.com/run/docs/deploying), [секреты Cloud Run](https://cloud.google.com/run/docs/configuring/services/secrets). Цены и доступность ресурсов проверяйте перед запуском.

## 4. Подключение сайта на Vercel

1. Откройте проект ArduHub → Settings → Environment Variables. Для Production установите `COMPILER_URL=https://адрес-сервиса/compile` и `COMPILER_SECRET` с тем же значением. Не используйте `NEXT_PUBLIC_`.
2. Если существуют старые `COMPILER_API_URL` и `COMPILER_API_KEY`, обновите или удалите их после проверки: сейчас старые имена имеют приоритет над новыми. Иначе сайт может продолжать обращаться к прежнему адресу.
3. Выполните Redeploy, новые переменные применяются после нового развёртывания.
4. Служебная `/dev/status` скрыта в обычном Production. Используйте Vercel Preview с теми же переменными для проверки. Если необходимо открыть её в Production, временно задайте `LOCAL_DEV_STATUS=true`, сделайте Redeploy, проверьте и затем удалите переменную с повторным Redeploy. Это откроет служебную страницу; не оставляйте её включённой постоянно.
5. Нажмите **«Скомпилировать Blink»**. Запрос идёт с сервера Next.js прямо в сервис, обходя кэш готовых решений приложения. Должно появиться **«Готово»** и время HTTP-компиляции в миллисекундах. Повторный запрос может попадать в кэш самого сервиса. Секрет в браузер не передаётся.
6. В уроке 2 измените задержку на `delay(500)`, нажмите «Запустить» и проверьте мигание. Простой код может работать через браузерный интерпретатор G-4; доступность реального сервиса подтверждается именно служебной кнопкой и `compile:smoke`.

## 5. Диагностика

| Ответ                    | Действие                                                              |
| ------------------------ | --------------------------------------------------------------------- |
| Нет конфигурации         | Задать обе переменные на сайте и повторно развернуть его              |
| 401                      | Сверить секреты сервиса и Next.js, включая старые COMPILER_API_*      |
| 429                      | Подождать освобождения двух задач; очередь намеренно не накапливается |
| 400 + diagnostics        | Проверить указанную строку программы; это не сбой сервера             |
| 503 compiler_timeout     | Посмотреть ресурсы контейнера и журналы Arduino CLI                   |
| 503 compiler_unavailable | Проверить образ, наличие CLI и ядра arduino:avr                       |
| Сетевой таймаут          | Проверить адрес, HTTPS, холодный старт и доступность /health          |

Техническая диагностика остаётся в служебной странице. В интерфейсе ученика сохраняется дружелюбный текст.

## Проверка в текущем окружении

В Windows-окружении 25.10.2026 команда `docker` отсутствует: локальный Docker build/run заблокирован отсутствием Docker, а не отмечен выполненным. Отдельно проверен настоящий Arduino CLI в доверенном локальном режиме: `/health`, Blink → HEX (11603 мс), синтаксическая ошибка → 400/строка 3, неверный ключ → 401, повтор → тот же HEX (2 мс). Это не подтверждает сборку Docker-образа и не означает подключение облачного сервиса. Установка Docker, проверка контейнера и внешнее развёртывание остаются шагами владельца.
